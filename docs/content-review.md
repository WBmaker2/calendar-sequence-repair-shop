# 콘텐츠 검수 기록 — 달력 순서 복원소

검수 기준일: 2026-08-28 · 근거 문서: `docs/plans/2026-08-28-calendar-sequence-repair-shop-implementation-plan.md`

## 1. 검수 범위와 원칙

- 이 앱의 모든 미션은 2026년 실제 그레고리력과 일치하는 고정 데이터만 사용하며 런타임 무작위 생성을 하지 않는다.
- 날짜 계산은 지역 시간대의 영향을 받지 않는 UTC epoch-day 정수 계산으로만 수행한다.
- 학생 이름, 실제 학급 사건, 위치, 사진, 생년월일을 입력받거나 저장하지 않는다. 행사는 모두 가상 행사다.
- 복수 정답이 가능한 미션은 검수된 복수 해법을 정식 결과로 인정한다.
- 이 문서는 자동 검증 항목과 사람 검수 항목을 구분한다. 자동 검증 통과가 교과 전문가 승인을 대체하지 않는다.

## 2. 고정 미션과 승인 답

| 미션 ID | 장면 | 학생이 하는 일 | 승인 답 (정답 관계) |
|---|---|---|---|
| `calendar-gap-01` | 2026년 9월 1~5일 | 빠진 3일과 목요일 예측 | 2026-09-03 · Thursday · 9월 2일 다음 날 |
| `calendar-week-02` | 2026년 9월 첫째·둘째 주 | 같은 월요일 두 칸 선택 | 2026-09-07과 2026-09-14 · 7일 차이 · Monday |
| `calendar-yesterday-03` | 2026년 9월 14일 월요일 | 어제·내일 카드 연결 | 2026-09-13 Sunday, 2026-09-15 Tuesday |
| `calendar-after-seven-04` | 2026년 9월 8일 화요일 | 일주일 뒤 칸 찾기 | 2026-09-15 · Tuesday · 7일 뒤 |
| `calendar-order-05` | 가상 행사 3건 (도서관·화단·체육) | 날짜 빠른 순서 배열 | 2026-09-05 → 2026-09-12 → 2026-09-21 |
| `calendar-order-05` 비고 | 도서관 9/5 토, 화단 9/12 토, 체육 9/21 월 | 순서만 판단, 요일 판단 아님 | 관계 `chronological-order` |

## 3. 요일 기준 fixture (실제 달력과 일치 확인)

- 2026-09-01 Tuesday · 09-03 Thursday · 09-05 Saturday · 09-07 Monday · 09-08 Tuesday
- 09-12 Saturday · 09-13 Sunday · 09-14 Monday · 09-15 Tuesday · 09-21 Monday
- 09-29 Tuesday · 09-30 Wednesday · 2026-10-01 Thursday · 2026-10-02 Friday
- 2026년 9월은 30일까지다. 9월 31일은 존재하지 않는 날짜로 콘텐츠와 입력 어디에도 등장해선 안 되며, 월 경계 미션의 오답 보기로만 "없는 날짜" 교육 목적으로 노출된다.

## 4. 용어와 문구 기준 (어린이용)

- 날짜 표기: `2026년 9월 3일 목요일` 형태. 판정 데이터는 zero-padded `YYYY-MM-DD`를 유지한다.
- 어제·오늘·내일, 일주일 뒤, 다음 날 표현은 초등 1~2학년 눈높이 문장으로 쓴다.
- 오답 피드백은 정답을 즉시 공개하지 않고 근거를 확인할 방향을 제시하고, 한 번의 수정 기회를 준다.
- 결과 화면은 점수·등급·순위 없이 최초 판단, 근거, 수정 결과를 보여 준다.

## 5. 오개념 방지 (misconceptionGuard)

| 미션 | 방지하려는 오개념 |
|---|---|
| `calendar-gap-01` | 달력 칸을 임의로 채워도 된다는 생각 → 앞뒤 날짜·요일 근거로 복원함을 강조 |
| `calendar-week-02` | 같은 요일이 아무 날짜나 될 수 있다는 생각 → 7일 차이 근거 제시 |
| `calendar-yesterday-03` | 어제·내일을 요일만으로 추측 → 달력 위치 근거 제시 |
| `calendar-after-seven-04` | 일주일 뒤를 5일·10일 뒤와 혼동 → 7일 뒤 같은 요일 근거 제시 |
| `calendar-order-05` | 요일만 보고 순서를 판단 → 날짜 숫자 크기 근거 제시 |
| `calendar-month-06` | 9월 31일이 존재한다는 생각 → 월 길이와 월 경계 근거 제시 |

## 6. 자동 검증 항목 (빌드가 강제)

- 미션은 정확히 6개이며 ID·선택지 ID·판정 ID가 코드·테스트·문서에서 동일하다.
- 모든 DateKey가 zero-padded `YYYY-MM-DD`이며 실제 달력상 존재하는 날짜다.
- visibleDates와 hiddenDates가 겹치지 않고, expectedAnswers가 UTC 계산 결과와 일치한다.
- 모든 미션에 sourceNote, reviewStatus(approved), misconceptionGuard가 있다.
- 자동 접근성 검사(serious/critical 0건), 네트워크·저장소 경계 테스트가 빌드 체인에 포함된다.

## 8. 한계 명시

이 앱은 교육 모형이며 실제 세계의 모든 달력 상황(윤년, 다른 월, 다른 연도)을 다루지 않는다. 판정과 근거는 2026년 9월 고정 미션 범위에서만 보장된다. 이 한계는 결과 화면 피드백과 본 문서에 함께 명시된다.
